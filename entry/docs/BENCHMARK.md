# Measuring which workflow works for Modus

This harness compares complete record-question workflows on the same frozen evidence scopes. It also compares document extraction separately, so an extraction failure is not confused with an agent-selection failure. Meta execution remains pending. Local TeleOCR execution is recorded separately and never presented as a provider response.

## Frozen suites and provenance

The private `evaluation/workflow_v1` suite contains eight development questions across four scenario/profile families and 24 held-out questions across eight other families. `evaluation/documents_v1` contains four development documents from two layout families and eight held-out documents from four different families. The document set contains seven PDFs and five PNG inputs, fourteen pages in total, visually verified by its separate author.

The authors did not inspect production parser/agent implementation or runtime prompts. Gold was authored separately, not generated by the evaluated tools. Both suites are model-authored synthetic research examples; independent human annotation and semantic review remain pending. Hashes, disjoint families and separate authors do not prove representative sampling, uncontaminated pretraining, clinical validity or error-free annotations.

Each suite has a `freeze.json` with input/annotation hashes. The candidate's source archive and protocol live under private `evaluation/baseline-*`. The runner records current code/prompt/configuration hashes, corpus identity, model alias, environment, exact schedule and budgets before executing. A changed method gets a new identity; do not pool different plans as though they were one comparison.

Public exports and Git ignore the entire `evaluation/` directory, including held-out source, gold, generators, previews and result ledgers. The private full-project handoff preserves it. The clean public candidate includes the harness and artificial tests, but needs an explicitly supplied private suite to execute the benchmark.

## Comparators

| Method | Actual behavior |
|---|---|
| `local_fixed` | Current production deterministic question router and record tools, with no model call. |
| `meta_single` | Fixed construction of all/per-metric inventory and conflict candidates, plus all/per-metric bound comparisons when available; one structured model call selects exact claims. Its eight or twelve tool reads and construction time are part of its cost. |
| `meta_agent` | Production bounded tool-selection loop with an injected budgeted transport; no substitute orchestration implementation. |
| `local_parser` | Existing deterministic PDF-text parser; unsupported images remain failed coverage cases. |
| `local_hybrid` | Deterministic layout-preserving PDF text parsing; PNG/JPEG use the explicitly installed local TeleOCR checkpoint. Primary resolution is 2,007,040 pixels, with at most one 1,003,520-pixel retry after verified truncation or unsupported output format. Valid-empty results, missing fields, runtime errors and benchmark scores never trigger retries. Both subattempts, costs and failures are retained. No provider fallback. |
| `meta_direct` | Existing structured document adapter followed by draft validation. No local fallback after model failure. |

The model question workflows share the frozen inputs, allowed tools, maximum rounds, output cap and serialized context-byte limit. Their actual information presentation, request count and tool reads differ intentionally: this is a workflow comparison, not an isolated model-intelligence ablation. The optional TeleOCR document method has its own pinned checkpoint, recorded prompt/decoding settings and bounded local worker; its setup and hardware requirements differ from the parser and Meta adapter.

## Run without credentials

Use the project's Python environment. Default commands only print a metadata/count plan, never task text or gold, and make zero provider requests:

```text
python scripts/compare_workflows.py
python scripts/evaluate_heldout_documents.py
```

Run only the development deterministic baselines:

```text
python scripts/compare_workflows.py --methods local_fixed --execute
python scripts/evaluate_heldout_documents.py --methods local_parser --execute
```

For development improvement work, use `python scripts/development_guard.py compare_workflows --methods local_fixed --execute` and `python scripts/development_guard.py evaluate_heldout_documents --methods local_parser,local_hybrid --execute`. The latter explicitly executes the installed local model for image cases. The guard refuses opening or statting held-out corpus files and writes a private access audit. It is an operator check, not an OS sandbox. Both normal development runners now load and verify only development annotations and their referenced inputs.

`scripts/compare_development.py --workflow RUN_DIRECTORY --documents RUN_DIRECTORY` compares new runs with the preserved baseline outputs. It verifies identities, frozen development input/gold hashes, schedules and source snapshots, regrades both outputs with the same strict grader, and requires baseline pass/fail outcomes to remain unchanged. Runtime-version scope IDs are recomputed against each version's bundle. This is saved baseline output replay, not a fresh baseline execution or controlled latency comparison. A canonical metric-specific arrival claim is required after typed metric filtering was added; the original baseline outcomes must still remain unchanged.

With a clean public extract, add `--suite PATH_TO_PRIVATE_SUITE`. Output goes into a new unique directory under private `evaluation/results/`; prior attempts are never overwritten. Three repetitions are the default for every selected method. Repeated deterministic executions are not independent evidence of model reliability.

## Live execution after access is configured

The same commands run live methods only with `--execute --allow-network`, a locally configured server key, and explicit positive request/output budgets. Never put a key in the command line, browser, report or chat. For a complete three-repeat development workflow comparison, the current worst-case upper bound is 168 provider requests and 268800 reserved output tokens; actual usage can be much lower. These are capacity limits, not an authorization to spend or a price estimate.

Example command shape (replace the budget placeholders deliberately):

```text
python scripts/compare_workflows.py --methods local_fixed,meta_single,meta_agent --execute --allow-network --max-requests REQUEST_CAP --max-output-tokens OUTPUT_CAP
python scripts/evaluate_heldout_documents.py --methods local_parser,meta_direct --execute --allow-network --max-requests REQUEST_CAP --max-output-tokens OUTPUT_CAP
```

Provider request count, reserved output tokens and UTF-8 request bytes are enforced before transport. Exact input tokens and money are not hard-capped using an unverified tokenizer or price. Provider-reported missing usage stays unknown. A depleted global authorization budget leaves denied attempts in the denominator and marks the comparison ineligible for paired interpretation; do not rank methods from that incomplete run. Provider calls have no automatic retries. The explicitly selected local OCR strategy has the one format/truncation retry described above, with at most 12 pages, 4,096 input tokens and 1,024 generated tokens per page per subattempt, and a 180-second worker timeout per subattempt. These process checks are not an OS sandbox or production resource-isolation claim.

## Holdout discipline

Only after candidate code, prompt, interpretation and budgets are frozen, add `--split holdout --unlock-holdout --holdout-reason "pre-registered final comparison"`. Execution records opening in a persistent access ledger. Reuse requires `--reuse-holdout` and is explicitly labelled as prior exposure. Local controls are operator safeguards, not an immutable external audit system. A reused split cannot be called newly blind after feedback-informed tuning.

Routine checks use artificial unit fixtures and the existing development gates. They never execute these held-out cases. Development plans and execution do not inspect held-out input files; the earlier corpus-creation cross-split audit is preserved as provenance. Public export prunes the private evaluation tree before traversing it.

## Grading and decisions

Question grading requires exact canonical tool claims, independent authored task relevance, correct evidence IDs, both captured scopes and the fixed supported/unsupported answer forms. Valid source IDs alone do not establish support. Document grading uses linked metric/value/unit/date/page rows as a multiset plus visible source-span support; marginal field matches cannot hide swapped associations. A parser/network error, truncated/filtered output, unsupported format or denied request is not a correct abstention.

Reports retain planned/completed/failed/missing counts, support/relevance/scope checks, all-trials case success, paired outcomes by case/repeat, provider identity when returned, usage and latency. Warm method latency includes candidate construction and failures but excludes shared context setup and separately recorded integrity checks. Families and repeats can be correlated; no significance or universal-best claim is manufactured from this small set.

Prefer the method that preserves authority/scope first, then achieves better task success and all-trials reliability, with request usage and latency as secondary tradeoffs. Real paired runs and human-reviewed labels are prerequisites for a stronger conclusion.

## Original frozen development checkpoint

Production local routing passed 3/8 distinct development tasks (9/24 repeated attempts). All 24 outputs were supported and scoped, but only nine matched the authored intended task. Local extraction passed 1/4 distinct documents (3/12 attempts); two image documents were explicitly unsupported and one PDF did not meet exact extraction requirements. These outcomes were retained without changing the production router, parser or prompts to fit the cases.

Early development runs remain alongside the final run. Initial timing included integrity checks; the final runner records that overhead separately. No held-out case or real Meta request was executed, and no model winner is established. All ten full-product goals and nine prompt roles remain intact.
