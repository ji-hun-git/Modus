## All nine registered roles

| Role | Full-project status | Entry disposition |
|---|---|---|
| `orchestrator` | `runtime_active_when_meta_enabled` | A separately bounded entry prompt may choose only record inventory/conflict/comparison/scoped-retrieval tools and exact previously emitted claims. It cannot widen scope, write records or execute code. Live behavior still needs measurement. |
| `extractor` | `runtime_active_when_meta_enabled` | Propose schema-constrained document facts with source excerpt/page. Human review precedes commit; unknown dates/units stay unknown. Actual Meta requests remain distinct from local parsing. |
| `evidence_selector` | `training_active` | Retain evidence-selection/abstention research. Training-data preparation is not training. No adapted selector is required for this entry milestone. |
| `normalization_review` | `design_only` | Deterministic validation/review flags support the current flow; a model normalization reviewer remains unactivated until it shows measured benefit. No silent unit/date conversion. |
| `reference_context` | `design_only` | Retain broader versioned-reference research outside this entry. No personalized medical interpretation through reference search. |
| `genetic_context` | `design_only` | Retain exact-variant/condition/assembly research outside this entry. No genetic interpretation tool or fixture in the runnable entry. |
| `evidence_critic` | `design_only` | Keep deterministic support/scope checks now. A future model critic must beat an appropriate baseline on frozen reviewed cases; it cannot grant authority, certify safety or silently rewrite source facts. |
| `followup_brief` | `design_only` | Preserve broader record-found/completion-unknown distinction outside the entry. Missing records never establish missed care; no care-plan assessment tool is exposed here. |
| `evaluation_reviewer` | `design_only` | May later assist failure classification over frozen actual outputs. Human/deterministic adjudication owns pass counts; no invented scores or selective reporting. |

Using all goals and prompts means keeping explicit ownership, intent and acceptance evidence. It does not mean activating every design-only agent or moving excluded capabilities into the contest build. Engineering subagents helping with UI, storage and QA are development collaborators, not additional runtime product agents.

## Claims that remain separate

- **Implemented:** actual code exists in the inspected build.
- **Tested:** a named check ran against a specific source/build and fixtures.
- **Live model used:** an actual provider/model request ran with recorded identity and outcome.
- **Released leading method used:** a pinned method/model executed under a documented configuration.
- **SOTA performance reproduced:** the exact benchmark/revision and credible comparator protocol were actually reproduced; Modus has not established this claim.
- **Eligible / submitted / production-ready:** each needs its own external or operational evidence, independent of code/tests.

The full project retains its existing evidence and pending work. This document changes no registry status to complete.
