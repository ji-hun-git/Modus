## Model availability and scope

Meta's [current model catalog](https://dev.meta.ai/docs/models) lists `muse-spark-1.3` for tool calling and structured document workflows, and `sam-3.1` for image/video segmentation. Catalog publication does not establish access for this account. It also states that Muse Wonder is unavailable in South Korea; no substitution or workaround is proposed.

SAM produces boxes and masks. Its possible role here is locating document regions, followed by measured extraction; segmentation alone does not demonstrate OCR, correct row association, source support or useful record reconciliation. It is an optional experiment after a concrete layout failure and a comparison protocol, not a P0 dependency.

The [official Prompt Guard 2 model card](https://huggingface.co/meta-llama/Llama-Prompt-Guard-2-86M) describes a benign/malicious prompt-attack classifier, a 512-token window, and separately licensed/gated model access. Its documented evaluation languages do not include Korean. Treat Korean performance and long-document chunking as unverified. It does not replace typed permissions, scope enforcement, source validation or abstention, and it is not a factual or medical correctness judge. No model was downloaded or agreement accepted.

The event page lists multiple Meta technologies; neither it nor the recorded requirements establish an obligation to integrate every model or fine-tune. A reliable, demonstrated Meta extraction/tool-selection contribution is more useful than adding optional components without evidence. This is an engineering priority judgment, not a prediction of judging results.

## Existing provider coverage and concrete gaps

At the start of this audit, `backend/modus/provider.py` used the fixed official endpoint, TLS verification, a 45-second request timeout and no automatic retries. Policy limits were six model rounds, 14 tool calls, eight selected claims and 1,600 completion tokens per agent call; extraction reserved 4,000 completion tokens. These are request/output limits, not a verified monetary or input-token cap.

Existing artificial tests cover disallowed tools, invalid multi-tool batches, unsupported claim selection, exact model identity, missing usage, sanitized generic request failures, unchanged records and no offline-success fallback (`test_entry.py`, `test_entry_adversarial.py`, `test_document_workflow.py`). The benchmark harness separately rejects length/content-filter interruption. Those tests do not establish deployed HTTP timeout/401/429/5xx behavior or real model reliability.

Two deployment gaps were found: shared telemetry dropped response/request IDs and failure categories; entry/extraction accepted syntactically valid payloads without examining explicit refusal or incomplete finish metadata. A transport completion can therefore precede a failed validation and must not be presented as a validated answer. The root agent authorized a focused repair and separate artificial tests; verification is appended below after completion.

The existing `scripts/smoke_meta.py` asks a broad kidney-history question. It is not bounded-entry proof and is explicitly not a prerequisite in `entry/docs/LIVE_COMPARISONS.md`. The appropriate small smoke uses one fixed synthetic document and the record-only agent, keeps records uncommitted, caps requests/output reservations, retains all failures, and defaults to preparation without network activity.

## Focused preparation repair verified

The root agent authorized the small code repair after this read-only review. `backend/modus/provider.py` now retains only bounded response/request IDs, HTTP status, returned finish reason and a finite failure category, in addition to actual usage/model/timing. Request IDs are taken only from `x-request-id` or `request-id`; absent or invalid IDs remain null. Exceptions, bodies, refusal text and arbitrary headers are never retained. Explicit refusal, length/content-filter interruption and unknown nonempty finish reasons fail before consumers can return partial claims or extracted observations. Older artificial responses may omit finish metadata; this remains unknown rather than an invented successful stop. A completed transport can still fail downstream schema or evidence validation.

`scripts/smoke_entry_meta.py` adds a record-only preparation command. Its fixed authored one-page PDF is separate from the authored nine-fact entry seed. The model extracts a proposal, then the existing bounded entry loop reads an isolated temporary seed store; proposed rows never enter that store. It cannot commit an import. Default execution writes only a uniquely named preparation report. Both `--execute` and `--allow-network` are required for the real adapter, and this audit did not use either to make a provider call.

The fixed maximum is seven adapter attempts: one extraction at a 4,000-token reservation and up to six agent calls at 1,600 each, totaling at most 13,600 reserved output tokens. No retry is made. The existing 14-tool-call/eight-selected-claim policy still applies. These are output/request bounds, not an input-token or monetary cap. Reports preserve attempted calls separately from confirmed network delivery, which is unknown for some failures; missing usage and request IDs remain unknown. Existing report paths cannot be overwritten. Injected transports always report `mock_transport_test`, zero provider requests and no live verification. Even a real successful smoke establishes only this path, not model performance, generalization or clinical reliability.

Focused verification: **28 artificial tests passed** in `backend/tests/test_entry_smoke.py` using the project virtual environment. Cases cover preparation without provider configuration, explicit network opt-in, unchanged records/no commits, budget reservation before dispatch, no retry, timeout, HTTP 401/429/503, malformed transport JSON/envelopes, malformed extraction/tool payloads, explicit refusal/incomplete outputs in both entry and extraction consumers, usage/ID retention on rejection, unknown metadata, and the history projection's allowlist. The initial test run had four test-fixture failures because a partial execution identity omitted required keys; the fixture was corrected to use the actual execution-context factory, then all 28 passed. No real response, held-out input or credential was used. Root owns full release gates, the resulting source-identity refresh, public manifest and API documentation.

Final operator-configuration follow-up: the real adapter branch loads the root `.env` only after both execution/network guards, with `override=False` so existing environment settings win. Preparation and injected transports never load that file, even when a mock run supplies the network flag. The smoke remains fixed to `muse-spark-1.3`; a differing `MODUS_MODEL` selected by the entry agent is blocked before that request with sanitized `model_mismatch`, not silently substituted. Two additional artificial cases verify loader arguments in isolation and the mock-plus-network-flag boundary; no real credentials or live-labelled test report are used. Final focused total: **30 passed**.
